Cost-Aware LLM Routing from Human Preferences

基于人类偏好的成本感知大模型路由

Using 100,000+ human preference votes, this study builds a cost-aware evaluation framework for LLM routing and shows that a price rule plus an embedding router cuts the cost of half the strong model's quality gain by 55%, while 7 semantic labels on just 6,700 votes come close to the embedding router.基于 10 万余条人类偏好投票，本研究建立了成本感知的大模型路由评估框架，并证明价格规则加 embedding 路由器能以低 55% 的成本拿到强模型一半的质量提升，而 7 个语义标签只用 6,700 票就接近 embedding 路由器的效果。

Evaluation framework and methods评估框架和实验方法

For each request, the router estimates the strong model's expected quality gain per unit of incremental cost; higher ratios go to the strong model first. Expected gain = P(strong wins) − P(strong loses); ties count 0, so ties go to the weak model.路由器为每条请求估计调用强模型的预期质量增益与增量成本之比，比值越高越优先路由到强模型。预期质量增益 = P(强模型胜) − P(强模型负)，平局记 0，因此平局时路由到弱模型。

Step 2: tiers第 2 步：定强弱

Cut at rating gaps在评分断层处切开

Bradley-Terry ratings. Tiering follows RouteLLM, but cuts at the two largest gaps; the middle 30 models are a buffer.Bradley-Terry 算评分。按评分分档参考 RouteLLM，改在两处最大断层切开，中间 30 个留作缓冲。

Step 3: read the prompt第 3 步：读懂问题

Two approaches两种方法

Approach 1: embeddings方案一：Embedding

e5-large encodes the prompt as a 1,024-d vector. R1 logistic regression as control, R2 matrix factorization as main; about 90k training votes.e5-large 把问题转成 1,024 维向量。R1 逻辑回归作对照，R2 矩阵分解为主，约 9 万票训练。

Approach 2: labels方案二：语义标签

Claude Haiku tags 7 readable fields such as task type and difficulty. R3 trains on about 6,700 votes; labeling costs about $1.Claude Haiku 打 7 个可读字段，如任务类型、难度。R3 只用约 6,700 票训练，打标约 $1。

Step 4: baselines第 4 步：基线

Two baselines双基线对照

Rating gap only, no prompt features; rating gap ÷ price gap (dollar axis, also layer 1 of the recommendation).只看评分差，不使用 prompt 特征；评分差 ÷ 价格差（美元口径，也是建议的第一层）。

10 rating-gap buckets按评分差分 10 档
Step 5: score第 5 步：打分

APGR

Shift requests to the strong model in router order; take the area under the quality-recovered curve. Random = 0.5, perfect = 1.按路由顺序逐步改发强模型，取收回质量比例曲线下的面积。随机=0.5，完美 =1。

Leakage control防泄漏
Split by prompt group. Dev set: 90,923 votes, 5-fold CV; held-out test set: 10,135 votes. Ratings refitted within each training fold.按 prompt 分组划分。开发集 90,923 票做 5 折交叉验证，留出测试集 10,135 票。评分在每折训练集内重新拟合。
Evaluation views评估口径
All pairs: every model pair pooled, reported by rating-gap stratum. Strong vs weak: strong tier against weak tier only.全配对：所有模型对合并，按评分差分层报告。强弱档：只看强档对弱档。
Cost axes成本轴
Call share (share of requests routed to the strong model) and dollars (incremental spend; only votes where the higher-rated model costs more).调用比例（路由到强模型的请求占比）和美元（增量花费，仅用高分方单价更高的票）。
Pre-registration预注册
Hyperparameters chosen by nested selection within training folds. Test set evaluated twice, each against pre-registered criteria, then sealed.超参数只在训练折内嵌套选择。测试集共评估两次，每次预先登记成功标准，评估后封存。

Conclusions and recommendations结论与建议

Ship a price rule with no prompt features first, then add a router that reads prompt features or embeddings.先上一条不使用 prompt 特征的价格规则，再加读取 prompt 特征或 embedding 的路由器。

Layer 1第一层−51%

Price-aware rule价格规则

Rank by rating gap ÷ price gap. No prompt features, no training, 45–51% cheaper than sending everything to the strong model. In another 33% of pairs, the higher-rated model is cheaper.按评分差 ÷ 价格差排序，不使用 prompt 特征、不训练模型，就比全发强模型省 45–51%。另有 33% 的配对高分方反而更便宜。

Layer 2第二层+0.083

Prompt-embedding router (R2)读取 prompt embedding 的路由器（R2）

Test-set APGR rises from 0.529 to 0.612, passing the pre-registered bar. Another 8–14% saved in dollars (point estimate). Largest gains on closely matched pairs.测试集 APGR 从 0.529 提升至 0.612，通过事先登记的标准。按美元再省 8–14%（点估计）。实力接近的配对收益最大。

75% → 50%

The model premium lies in open-ended questions模型的溢价在开放式问题上

Strong tier wins 75% on advice and planning, but only 50% on bug fixes and definite-answer questions, with 28% ties.推荐、规划题强档赢 75%；改 bug、有确定答案的题只赢 50%，平局 28%。

6.7k vs 90k

Labels for cold start, embeddings at scale冷启动用标签，数据多用 embedding

7 labels on about 6,700 votes match embeddings on 90k, at about $0.22 more per 1,000 requests and about 1 s more latency.7 个标签只用约 6,700 票就追平 9 万票的 embedding，代价是每千次多约 $0.22、多约 1 秒延迟。

+0.02 … +0.08

Router gains depend on the product setup路由器的收益有多大，取决于你的产品是什么样的

With many model pairs: up to 0.054 (dev) / 0.083 (test). With one fixed pair: only 0.02–0.03 above random (dev).多对模型可选时，最多提升 0.054（开发集）/ 0.083（测试集）；只有固定一对模型时，只比随机高 0.02–0.03（开发集）。

1.0 s

The main cost is inference latency, not call cost主要代价是推理延迟，而非调用成本

Routing inference costs about $0.02 per 1,000 requests; the bottleneck is CPU embedding, with 1.0 s P90 latency. Move to GPU or a smaller embedding model before launch.路由推理成本约每千次请求 $0.02；瓶颈在 CPU 上的 embedding 计算，P90 延迟 1.0 秒。上线前可迁移至 GPU 或改用更小的 embedding 模型。

Stacking adds nothing叠加没有额外收益

No advantage on the dollar axis美元口径没有优势

Routers trained only on strong-vs-weak votes do not beat rating gap ÷ price gap (R3 dev −0.009, test 0.000); too few votes per pair.只用强弱档票训练的路由器都没超过「评分差 ÷ 价格差」（R3 开发集 −0.009，测试集 0.000），每对模型票太少。

No routing gain on deterministic-answer prompts确定性答案问题上路由无增益

Limitations局限

  • Arena is not the target user base. Voters, prompt mix and pairings are set by Arena; re-validate on your own traffic before launch.Arena 不是目标用户。投票人、prompt 分布和配对都由 Arena 决定，上线前要用自己的流量再验证。
  • Labels are preferences, not correctness. 37% of repeated prompts get contradictory votes; majority-vote ceiling 79.5%.标签是偏好，不是正确率。重复 prompt 有 37% 结论矛盾，多数票天花板 79.5%。
  • Costs are underestimated. Hidden reasoning tokens excluded; the strong tier has more reasoning models.成本被低估。没算隐藏思考 token，强档里推理模型更多。
  • Small test set. Strong vs weak has only 999 votes; intervals about 3× wider than dev.测试集小。强弱档只有 999 票，区间宽度约是开发集的 3 倍。
  • Lower bound is dev-only, and ratings are not adjusted for answer length or style.下限只有开发集的数，评分也没有扣除回答长度和风格的影响。
